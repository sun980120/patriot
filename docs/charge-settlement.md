# 추가 비용 정산과 업무 화면

## 계산 기준

- 실제 총지출 `C`, 참가자 실납부액 `P`, 예정 회비 지원금 `S`를 구분한다.
- 실제 지원 배정 = `min(S, C)`.
- 참가자 예산 부담 = `C - 실제 지원 배정`.
- 정산 잔액(참고) = `max(P - 참가자 예산 부담, 0)`.
- 회비 순부담 = `max(C - P, 0)`, 회비 순유입 = `max(P - C, 0)`.
- 지출 장부의 지원/참가자 배정 합계는 반드시 `C`와 같아야 한다. 예정 지원금 전액을 실제 사용액보다 크게 지출로 기록하지 않는다.
- 수입은 참가자 실수납 `P`를 이미 포함한다. 정산 잔액 참고 내역은 같은 돈이므로 총세입에 다시 합산하지 않는다.
- CSV/Excel도 총세입과 연도 증감을 같은 기준으로 계산한다. 정산 참고 금액은 별도 CSV 영역/Excel 시트로 분리한다. 기존의 `기타 세입 - 지출` 요약 대신 `총 세입`, `연도 증감`, `정산 참고 금액(총세입 제외)`를 제공한다.

예: 사용 100,000원 / 실납부 60,000원이면 회비 순부담은 40,000원이다.
하지만 '정산 잔액 60,000원'만으로 회비 순부담을 계산할 수는 없다.
사용 100,000원 / 예정지원 40,000원 / 실납부 120,000원이면 정산 잔액은 60,000원이어도 회비 순유입은 20,000원이다.

## 저장과 수정

- 정산 전 확인창에서 실제 지출, 실납부, 회비 순부담/유입, 정산 참고 잔액을 확인한다.
- 정산 변경 작업은 같은 추가 비용 그룹 행을 잠근다. 납부 상태/금액 변경과 정산/정산 수정/삭제가 같은 그룹에서 겹치지 않도록 한다.
- 정산 완료 이후에는 납부 상태나 금액을 바로 변경할 수 없다. 정산 수정 모드로 전환해야 한다.
- 정산 수정 모드에서도 이전에 확정한 장부는 유지한다. 새 정산이 성공하면 관련 지출/참고 세입을 같은 트랜잭션에서 교체한다.
- 정산 연결 지출/세입은 일반 세입·지출 삭제 API로 개별 삭제할 수 없다. 재정 관리의 정산 항목에서 수정한다.
- 기존 API 경로/요청/응답 필드는 유지한다. 정산 완료 상태에서의 중복 정산과 개별 삭제는 400 업무 오류로 거절한다.

## 기존 기록 확인

기존 코드로 예정 지원금이 실제 사용액보다 크게 기록된 정산은 자동 보정하지 않는다.
화면은 기록 지출과 실제 사용액이 다르면 경고를 표시한다.
운영자는 원본 장부를 백업하고 참가자 입금 및 사용 증빙을 확인한 뒤, 해당 항목만 정산 수정 → 재정산한다.

아래 조회는 읽기 전용이다. 애플리케이션이 자동 실행하지 않는다.

```sql
WITH recorded AS (
  SELECT charge_group_id, SUM(amount) AS total_expense
  FROM expense_entries
  WHERE charge_group_id IS NOT NULL
  GROUP BY charge_group_id
)
SELECT g.id, g.title, g.support_amount, g.actual_cost,
       COALESCE(r.total_expense, 0) AS recorded_expense
FROM charge_groups g
LEFT JOIN recorded r ON r.charge_group_id = g.id
WHERE g.settlement_completed = TRUE
  AND g.actual_cost IS NOT NULL
  AND COALESCE(r.total_expense, 0) <> g.actual_cost;
```

## UI 기준

- 대시보드, 회비 관리, 캘린더, 전술 보드, 회원 관리, 재정 관리, 감사 로그, 내 정보의 페이지 제목은 24px/굵게로 통일한다.
- 공통 `PageHeading`과 업무 화면 스타일로 6px 컨트롤, 16px 섹션 제목, 평면 구분선과 표 중심 배치를 사용한다.
- 캘린더는 월 이동 아이콘과 일정 추가 명령을 제공한다. 반복 일정·제외일과 날짜 선택 동작은 유지한다.
- 전술 보드는 과도한 소개 영역을 없애고 편집 명령과 코트를 우선한다. SVG 코트와 편집/재생 엔진은 변경하지 않는다.
- 재정 관리는 전체 내역 / 추가 비용 정산 / 기타 세입 / 지출 탭으로 분리한다.
- 로컬 샘플 데이터 모드는 상단에 명시한다. 운영 API가 설정된 경우 샘플로 대체하지 않는다.

## 검증과 배포

`npm run test:settlement`, `npm run test:finance`, `npm run build`, `cd backend && ./gradlew test`.
프론트엔드와 백엔드는 같은 정산 예제 JSON으로 회귀 검증한다.
DB DDL, 환경변수 추가는 없다. 백엔드 수정 후 프론트엔드를 배포한다.
실제 PostgreSQL의 동시 요청/잠금/롤백 통합 검증과 운영 장부 보정은 별도 수행한다.
롤백은 웹/서버를 이전 버전으로 되돌리되, 이미 정산한 장부를 자동 복원하지 않는다. 원본 기록/증빙과 감사 로그로 별도 검토한다.
