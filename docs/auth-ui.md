# 로그인과 동호회 가입 화면

## UI와 흐름

- 공통 `AuthShell`로 클럽 로고, 로그인/가입 이동, 흰 배경과 제한된 폼 너비를 사용한다. 작은 화면은 단일 열로 표시한다.
- 로그인은 아이디/비밀번호 라벨, 비밀번호 보기, 자동 로그인 선택, 인라인 오류, 진행 중 비활성화를 제공한다.
- 자동 로그인 쿠키와 갱신 동작은 기존 구현을 유지한다. 브라우저 저장소가 차단되어도 로그인 성공 후 화면 이동은 막지 않는다.
- 가입은 계정 정보와 회원 정보를 구분한다. 비밀번호 확인과 생년월일/필수 항목 검증을 추가하고 주소 검색 및 전화번호 표시를 유지한다.
- 신청 성공 시 폼을 정리하고 승인 대기 상태를 표시한다. 자동 승인하거나 자동 로그인하지 않는다. 실패 시 입력값은 유지한다.
- 기존 서버 비밀번호 강도/인증/가입 승인 정책은 변경하지 않는다.

## API와 보안

- 기존 `POST /api/auth/login`, `POST /api/auth/signup`, `POST /api/auth/refresh` 요청/응답과 오류 형식은 유지한다.
- 비밀번호 확인 값은 화면 검증에만 사용하고 서버로 보내지 않는다. 비밀번호/토큰을 로그에 기록하지 않는다.
- 로그인 쿠키는 기존 서버 액션의 HttpOnly, SameSite, Secure 정책을 유지한다.
- 브라우저 검증은 보조 수단이며 최종 인증과 가입 검증은 서버에서 수행한다.
- DB 구조, 환경변수, 관리자 권한, 승인 절차 변경은 없다.

## 검증

```sh
npm run test:auth
npm run test:dashboard
npm run build
```

테스트 API로 로그인 성공/실패, 자동 로그인 유지/해제, 갱신 후 이동, 가입 비밀번호 불일치/중복 아이디/완료 상태를 확인한다. PC 및 320/390/768/1024/1440px 화면의 입력창/버튼/가로 넘침을 확인한다.
주소 검색 콜백은 테스트 응답으로 검증했다. 실제 Kakao 주소 검색 팝업, 모바일 Safari 자동완성과 키보드 동작은 별도 기기/네트워크에서 확인해야 한다.

## 배포와 롤백

이번 인증 화면/대시보드 변경은 웹에만 적용한다. 기존 인증 서버 API를 사용하며 API/DDL 마이그레이션은 필요 없다. 개발 환경에서 기존 계정, 승인 대기 계정, 자동 로그인 계정으로 확인한 뒤 배포한다.
화면 문제는 이전 웹 버전으로 롤백한다. 가입 신청이나 납부 데이터는 화면 롤백으로 취소되지 않는다.
