# 관리자 회비 관리

## 역할별 대시보드

- 대시보드는 읽기 전용 운영 요약이다. 납부/취소/면제/알림/이체 안내 등의 처리는 `/dashboard?view=dues`의 회비 관리에서만 제공한다.
- 관리자 대시보드는 핵심 요약형이다. 누적 잔액, 선택 연도 세입/지출, 전체 미납액을 먼저 표시하고 처리할 일과 해당 월 납부율/일정을 배치한다. 월 납부율은 연간 개월분 합계가 아니라 선택한 조회 월의 대상 회원 기준이다. 미래 연도는 첫 표시 월의 선납 현황으로 표시한다.
- 긴 전체 미납/면제 목록과 재정 집계 내역은 펼침 영역에 두되 모든 회원과 전체 기간을 유지한다. 미납 검색과 회비 관리 연결도 유지한다.
- 정산 대기는 정산 미완료, 참가자 존재, 전원 납부 완료인 추가 비용만 집계한다. 미납 추가 비용 건수는 별도로 표시한다.
- 전체 미납 집계는 개설된 모든 회계연도의 현재 월까지를 포함한다. 현재 월을 납부했더라도 과거 미납이 있으면 포함하고, 미납 회원 수를 임의로 6명으로 자르지 않는다.
- 대시보드의 개인별 링크는 회원 ID와 미납/면제 월을 전달한다. 전체 미납 링크는 `status=arrears`를 전달해 회비 관리에서도 현재 월 납부 여부와 무관하게 전체 미납 회원 범위를 유지한다. 다른 연도에 미납이 있으면 별도로 표시한다.
- 누적 잔액은 누적 세입 - 누적 지출로 계산한다. 누적 세입/지출/잔액은 동일한 전체 기간을 사용하고, 선택 연도 수치는 별도 요약으로 표시한다. 이후 회계연도에 배정된 실제 납부금(선납)도 누적 수입에 포함한다.
- 월회비는 납부 완료 기록의 실제 금액을 사용한다. 추가 비용 납부와 연결된 정산 잔액 세입을 중복 집계하지 않는다. 운영 DB 직접 대조 없이 코드와 샘플 데이터로 검증한 계산 기준이다.
- 회비 관리·캘린더·회원 관리·재정 관리·내 정보·알림·전술 보드에 공통 앱 메뉴를 적용한다.
- 모바일은 메뉴 서랍과 한 열 배치로 전환한다. 서랍을 열고 데스크톱 폭으로 바꾸면 모달 상태와 스크롤 잠금을 해제한다.
- 다가오는 일정은 캘린더와 같은 반복/제외일 계산을 사용한다. 다음 60일에서 취소/완료 일정과 이미 끝난 당일 시간 일정을 제외하며, 여러 날 일정은 한 번만 표시한다.
- 일정 클릭 시 캘린더의 해당 날짜를 열고, 최근 거래는 실제 기록 시간순으로 표시한다. 날짜 없는 자료는 임의 날짜를 만들지 않고 `—`로 표시한다.
- `PaymentResponse`에 선택적으로 소비 가능한 `updatedAt` 필드를 추가했다. 납부 처리와 조회에 기록 수정일을 포함하며 DB 컬럼 추가는 없다. 세입/지출의 기존 `createdAt`도 화면에 연결한다.
- 일반 회원은 본인의 미납 회비 또는 미납 추가 비용이 있을 때만 납부 요약을 클럽 재정 위에 표시한다. 납부할 항목이 없으면 0원 요약/빈 카드를 숨기고 클럽 재정을 첫 섹션으로 제공한다. 추가 비용만 남은 경우에도 그 항목을 먼저 표시한다. 선택 연도 실제 납부 합계에는 선납도 포함한다.
- 관리자와 회원 모두 대시보드에서 읽기 전용 세입/세출 상세를 조회한다. 기타 세입과 지출은 항목별로, 월회비는 월별 수납 합계로, 추가 비용은 그룹별 실제 수납 합계로 표시한다. 합산 항목의 일자는 가장 최근 실제 수납일이며 없는 날짜는 만들지 않는다. 정산 참고 잔액은 중복 세입에서 제외한다. 모든 항목의 합계는 동일 연도 재정 요약과 일치해야 한다.
- 회원 재정 조회에는 다른 회원 이름/아이디/개별 납부 상태를 표시하지 않고 추가/삭제/수정 작업도 제공하지 않는다. 나의 최근 납부와 면제 내역은 본인에게만 한정한다. 세입/세출의 전체 보기와 키보드 탭 전환을 제공한다.

## 동작

- 웹: 회원 이름 고정 연간 표, 월 제목 클릭으로 기준 월 변경, 이름 검색, 연간 납부액/누적 미납액, CSV 내보내기. 상단 구분선과 조회 기준 드롭다운은 제거한다.
- 간사/가입 자동/수동 면제를 구분하고, 수동 사유와 자동 면제 시작일·횟수를 표시한다. CSV에도 면제 내용을 포함한다.
- 모바일: 현재/과거 월은 미납, 미래 월은 예정 목록을 기본 표시. 연간 요약에서 회원별 월 내역 조회와 선납 처리.
- 납부 완료 기록은 현재 회원 등급이나 가입일이 달라져도 보존한다.
- 미납은 한국 시간 기준 현재 월까지의 납부 대상만 집계한다. 미래 월은 예정, 가입 이전 월은 가입 전으로 표시한다.
- 예정 회비는 개인/일괄 선납할 수 있다. 납부하면 완료로, 미래 월 선납을 취소하면 다시 예정으로 표시한다. 면제/가입 전 회비 제한은 유지한다.
- 가입 전 회비는 대시보드 알림 대상과 월회비 푸시 대상에서도 제외한다.
- 연간 합계/CSV는 해당 회계연도에 설정된 표시 월과 활성 승인 회원 기준이다.
- 개별 납부/면제 및 일괄 처리는 서버 응답이 성공한 뒤 화면에 반영한다.
- 일반 회원은 납부 안내에서 계좌 정보 복사, 토스/카카오뱅크 실행을 이용한다. 자동 입금 확인은 포함하지 않는다.
- 일반 회원의 예정 월에서도 선납 이체 안내를 제공한다. 실제 완료 처리는 관리자/간사가 입금 확인 후 수행한다.

## 일괄 납부 API

`PATCH /api/payments/bulk-paid`

인증: JWT, `ADMIN` 또는 `SUPER_ADMIN` 권한. 기존 PATCH payments 보안 규칙을 적용한다.

```json
{
  "fiscalYearId": "회계연도 UUID",
  "month": 11,
  "memberIds": ["회원 UUID"]
}
```

- `fiscalYearId`: 필수 UUID, 존재하는 회계연도.
- `month`: 필수 1~12, 해당 회계연도의 표시 월. 미래 월도 선납할 수 있다.
- `memberIds`: 필수, 중복 제거 후 1~200명, null UUID 불가.
- 비활성/승인 대기/간사/가입 전/면제 대상이 포함되면 전체 요청을 거절한다.
- 이미 납부된 항목은 취소하거나 금액을 덮어쓰지 않는다. 재요청해도 완료 상태를 유지한다.
- 응답: 기존 `PaymentResponse` 배열. `id`, `fiscalYearId`, `memberId`, `month`, `paid`, `chargedAmount`, `appliedGrade`, `manualExempt`, `exemptionReason`.
- 오류: 입력/업무 검증 실패 400 (`ApiErrorResponse`: timestamp, status, error, message, path), 인증 실패/권한 부족은 Spring Security에서 거절.
- 전체 검증, 변경, 감사 로그는 한 서비스 트랜잭션으로 처리한다.
- 단일/일괄 납부 및 면제 변경은 회원 행을 같은 순서로 잠근다. 회원별 납부 이력과 회계연도는 일괄 조회한다.

기존 toggle API에는 선택 필드 `expectedPaid`를 추가했다. 요청 시 화면에서 확인한 상태를 보내면 다른 관리자의 변경 이후 재토글되는 것을 방지한다. 필드를 생략하는 기존 클라이언트는 이전 동작을 유지한다. 응답과 exemption API 요청은 유지한다. 자동 면제 계산은 수동 면제 월을 차감하지 않도록 프론트엔드와 일치시켰다.

개별 선납은 `PATCH /api/payments/toggle`에서 동일한 `TogglePaymentRequest` (`fiscalYearId`, `memberId`, `month`, 선택 `expectedPaid`)를 사용하고 기존 `PaymentResponse`를 반환한다. 납부할 대상 월과 가입 전 여부를 서버에서 검증한다. `ADMIN`/`SUPER_ADMIN` 권한과 기존 오류 형식은 유지한다.

## 검증

```sh
npm run test:dues
npm run test:dashboard
npm run test:finance
npm run build
cd backend
./gradlew test
```

서비스 테스트: 등급별 금액, 이미 납부된 요청, 전체 검증 전 변경 방지, 수동/자동 면제, 비활성/미승인/간사/가입 전/잘못된 월 거절. 미래 월 개인/일괄 선납 허용, 선납 재요청 금액 보존, 미래 월 면제와 가입 전 제한.
웹 보안/컨트롤러 테스트: 관리자 허용, 회원 거절, 비인증 거절, 요청 검증/배치 크기 제한.

수동 확인: 웹에서 미납 또는 예정 필터 → 체크박스 선택 → 확인창 → 입금 확인. 모바일에서 월 이동, 예정 자동 필터, 연간 요약, 선납/취소 후 상태 확인. 일반 회원은 예정 월에서 이체 안내만 열리고 관리자 작업을 할 수 없어야 한다.
저장 실패 시 기존 상태가 유지되고 확인창이 남는지 확인한다. 운영 DB에서 검증용 납부 변경을 실행하지 않는다.

## 배포와 롤백

- 백엔드를 먼저 배포한 뒤 프론트엔드를 배포한다. 기존 백엔드에는 신규 일괄 API가 없다.
- DB DDL/마이그레이션/환경변수 추가는 없다.
- 배포 후 관리자 권한, 기존 개별 납부/면제, 일괄 처리, 감사 로그를 개발 환경에서 확인한다.
- 롤백 시 프론트엔드를 먼저 이전 버전으로, 필요하면 백엔드도 이전 버전으로 되돌린다.
- 이미 처리한 납부 데이터는 애플리케이션 롤백으로 취소되지 않는다. 오류 데이터는 감사 로그를 확인해 별도로 정정한다.
- 실제 PostgreSQL에서 잠금 대기/동시 요청과 트랜잭션 롤백을 검증하는 통합 테스트는 별도 DB 환경이 필요하다.
